# opcua.c3l

Pure C3 OPC UA client library: UA binary over opc.tcp, a sans-IO core (`Machine`) and a blocking adapter (`Client`) over a
`Transport` (`TcpTransport` is included). Version 0.1.0, MIT licensed.

## Status

Working and tested against two independent servers (open62541 v1.5.10 and asyncua 2.1.0, both with SecurityPolicy None):
HEL/ACK, secure channel open / renew (with retry) / close, anonymous and user name sessions, keep-alive, GetEndpoints,
FindServers, FindServersOnNetwork, Browse with continuation points, TranslateBrowsePathsToNodeIds, Read, Write, Call,
multi-chunk messages, the redacted trace, the `uatool` example. Not implemented: subscriptions and monitored items, signing and
encryption, reverse connect, history, node management.

### Security status

* SecurityPolicy **None** only. Anything else is refused with `SECURITY_UNSUPPORTED` before a byte is sent.
* A user name and password travels in **clear text** under policy None, so it is refused unless `Config.allow_cleartext_password`
  is set (`--allow-cleartext-password` in `uatool`), and a token policy that names a real security policy is refused even then.
  The password is overwritten in memory after it was used.
* Writing is explicit: `Client.write` and `Client.call` fail with `WRITE_NOT_ALLOWED` unless `Config.allow_write` is set;
  `uatool write` refuses without `--allow-write`.
* The trace (`Client.verbose`, `uatool --verbose`) is redacted: headers, type ids and sizes only; never a token, a password or
  a message body.
* Every length announced by the peer is checked against `Limits` and the bytes that are actually there before anything is
  allocated.

## Client use

```c3
TcpTransport tcp = tcp_connect("127.0.0.1", 4840)!;
Transport t = &tcp;                                   // an explicit interface cast, a TlsTransport is passed the same way
Client* c = client_connect(mem, t, "opc.tcp://127.0.0.1:4840")!;
defer c.free();                                       // also closes the transport
DynamicArenaAllocator arena;
arena.init(mem, 8192);
defer arena.free();
c.open_session()!;
DataValue v = c.read(&arena, nodeid_num(0, 2259))!;   // results live in the allocator you pass: use an arena
c.close()!;
```

A fault is a fault; a Bad status of a single node is data (`DataValue.status`, `BrowseResult.status_code`). `Client.last_status`
holds the status of the last `SERVICE_FAULT`.

### Duty of an idle program

There are no hidden threads. The channel renewal and the session keep-alive only run while the program is inside a `Client` call.
A program that waits between calls must call `Client.service(max_wait)` at least every `Client.next_deadline()`; every other
call starts by running the timers that are overdue (an overdue renewal goes out before the request), but a channel or session
the server has already dropped cannot be recovered by that (the next call then fails with `TIMEOUT`).

### Memory contract of the decoders

Every decoded value (strings, byte strings, arrays, structures with arrays) is allocated from the allocator you pass to the
decoder, and nothing is released when a decode fails half way: the children of the elements decoded so far stay allocated.
Pass an arena or the temporary allocator (for example a `DynamicArenaAllocator` per response) and free it as a whole.
The `Machine` and the `Client` follow the same rule: the allocator you give to a call receives the decoded response.

### Null versus empty

A `String`, a ByteString and an array are **null** when their pointer is null (the zero value) and **empty** when the pointer is
not null and the length is 0; the two are different on the wire (length -1 versus 0) and round-trip unchanged. Use `is_null`,
`bytes_is_null`, `null_string()`, `empty_string()` and never `len == 0` when the difference matters. A default-initialised request
struct therefore encodes every string and array as null.

### Error model

Faults (`faultdef` in `fault.c3`) are used for failures of the operation, grouped by prefix: codec (`TRUNCATED`, `BAD_LENGTH`,
`BAD_ENCODING`, ...), framing (`BAD_CHUNK`, `BAD_HANDSHAKE`, `TOO_MANY_*`, ...), channel and session (`TOKEN_UNKNOWN`,
`SESSION_LOST`, ...) and service (`SERVICE_FAULT`, `BAD_RESPONSE`, `EMPTY_REQUEST`, `WRITE_NOT_ALLOWED`, ...). The numeric status of
a `ServiceFault`, an `ERR` message or a failing `ServiceResult` is in `Machine.last_status` / `Client.last_status`. **A Bad status
of one node or one result is data**, not a fault: `DataValue.status`, `BrowseResult.status_code`, `CallMethodResult.status_code`.
`TIMEOUT` comes from the deadlines of the machine (handshake, request, renewal) or from a transport read or write timeout, never
from anywhere else. After a fault of `Machine.feed` or `handle_timeout` the machine is FAILED: drain its events (every pending
request has been answered with `Bad_ConnectionClosed` first) and reconnect with a new machine.

### Limits

Every length a peer announces is checked against `Limits` and against the bytes that are actually there before anything is
allocated. Each limit is accepted at its value and refused one above it (`limits_exact_test.c3`); a 0 in the browse fields of a
hand-built `Limits` means the default.

| field | default | refused with |
|---|---|---|
| `max_string_length` | 1 MiB | `BAD_LENGTH` |
| `max_bytestring_length` | 16 MiB | `BAD_LENGTH` |
| `max_array_length` | 1 000 000 | `BAD_LENGTH` |
| `max_matrix_elements` | 1 000 000 | `BAD_LENGTH` |
| `max_depth` | 32 | `DEPTH_EXCEEDED` |
| `max_message_size` | 16 MiB (reassembled message) | `MESSAGE_TOO_LARGE` |
| `max_chunk_count` | 64 | `TOO_MANY_CHUNKS` |
| `max_pending_messages` | 16 (partial messages) | `TOO_MANY_PENDING` |
| `max_reassembly_bytes` | 16 MiB (all partial messages together) | `MESSAGE_TOO_LARGE` |
| `max_outstanding_requests` | 64 | `TOO_MANY_PENDING` |
| `max_browse_pages` | 1000 (`BrowseNext` rounds of one `Client.browse`) | `TOO_MANY_PAGES` |
| `max_browse_references` | 1 000 000 (references merged by one `Client.browse`) | `TOO_MANY_REFERENCES` |
| `max_browse_bytes` | 256 MiB (100 bytes per merged reference plus its names) | `TOO_MANY_REFERENCES` |

### Write and call safety

`allow_write` (default false) is checked by the library before anything is queued: `send_write`, `send_call`, `Client.write`
and `Client.call` fail with `WRITE_NOT_ALLOWED`. One flag covers Write and Call because a method call can change state.

### Using TcpTransport

`TcpTransport` writes with the standard library's `send`, which does not set `MSG_NOSIGNAL`: an application that writes to a
connection the peer has already closed must ignore `SIGPIPE` (or it is terminated by the signal on POSIX systems).

### Servers that announce more than they enforce

A server's `MaxRequestMessageSize` is applied to every request (`MESSAGE_TOO_LARGE`, nothing sent). Some servers announce a
value that is smaller than what they accept (asyncua: 65536); `Config.ignore_server_request_limit` switches the check off.

## Peer tests

`c3_test` cannot pass environment variables, so the peer tests read `OPCUA_PEER_URL`, `OPCUA_USER`, `OPCUA_PASSWORD`,
`OPCUA_NODE_INT32`, `OPCUA_NODE_DOUBLE`, `OPCUA_NODE_STRING`, `OPCUA_NODE_ARRAY`, `OPCUA_NODE_METHOD_OBJECT`,
`OPCUA_NODE_METHOD`, `OPCUA_METHOD_KIND` (`add` or `string`) and `OPCUA_PEER_PID` from the environment or, when a key is unset,
from `peers/peer.env` (`KEY=value` per line, git-ignored; the path can be set with `OPCUA_PEER_ENV`). Without a URL every peer
test prints `SKIP: no peer configured` and passes; a test that cannot run against the configured peer prints `SKIP: <reason>`.
`OPCUA_VERBOSE=1` prints the redacted trace of the peer tests to stderr; observations go to `peers/observed.log`.

`peers/peer.sh start|stop open62541|asyncua` starts a peer (run only) and writes `peers/peer.env`;
`peers/run-peer-suite.sh <peer>` runs the whole suite against it. What the two peers do differently is in
`src/test/peer/QUIRKS.md`, real captured exchanges are in `src/test/peer/CAPTURES.md`.

## uatool

```
uatool endpoints <opc.tcp://host:port>
uatool browse    <url> [--node ns=0;i=85] [--depth 1]
uatool read      <url> <nodeid>... [--attr value|browsename|displayname|datatype]
uatool write     <url> <nodeid> <type:value> --allow-write [--user U --password P --allow-cleartext-password]
```

Build with `tools/build-uatool.sh`. Exit codes: 0 ok, 1 error, 2 usage or refused. `--verbose` prints the redacted trace.
`--password-env NAME` reads the password from an environment variable.

## Versioning

The version is written in `project.json` (`"version"`) and in `const String VERSION` in `types.c3` (`opcua::VERSION`, printed by
`uatool --version`); a test keeps them equal. Bump both with `c3c compile-run tools/bump_version.c3 -- 0.2.0` from the repository root.

## Part of the C3 plant automation libraries

Pure C3 building blocks for plant data infrastructure: read PLCs over S7, Modbus and OPC UA, move the
data over MQTT, and protect it with TLS. Each library works on its own; together they form the base for
an edge gateway.

- [mqtt.c3l](https://github.com/konimarti/mqtt.c3l): MQTT 3.1.1 and 5.0 client (sans-IO core, blocking client, `mqttc`)
- [modbus.c3l](https://github.com/konimarti/modbus.c3l): Modbus TCP and RTU client and server (`mbtool`)
- [s7.c3l](https://github.com/konimarti/s7.c3l): Siemens S7comm client for S7-300/400/1200/1500 (`s7tool`)
- **opcua.c3l** (this library): OPC UA binary client with generated types (`uatool`)
- [tls.c3l](https://github.com/konimarti/tls.c3l): TLS 1.2/1.3 transport on OpenSSL 3 with certificate and hostname checks (`tlsc`)
